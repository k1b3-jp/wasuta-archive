# わーすた・タイムミュージアム（仮）企画書

作成日：2026年11月8日／版：0.1／状態：検討用たたき台・未承認

## 1. 企画の核

**わーすたの歴史を、メンバーそれぞれの言葉とともに旅するデジタルミュージアム。**

公式と歴代メンバーの公開発信を出典付きで整理し、公演・楽曲・活動の出来事を、当時と後年の両方の視点からたどれる体験をつくる。利用者は展示を探索し、同じ出来事を語る複数の記録に出会い、自分の思い出ともつなげられる。

マネージャーとして歴史を変更する仕組みは採用せず、「当時の情報を順に知る」「別のメンバーの視点に切り替える」「楽曲と公演のつながりを発見する」ことを遊びにする。

## 2. 想定する利用者と価値

| 利用者 | 得られる体験 |
|---|---|
| 長く応援してきた人 | 当時の記憶を振り返り、見逃していた発信や別の視点に出会う |
| 最近知った人 | 前提知識がなくても、出来事と楽曲を手掛かりに歴史を理解する |
| 特定メンバー・楽曲に関心がある人 | 好きな入口からグループ全体の歩みに触れる |

最初の試作は、日本語で閲覧する既存ファンと新規ファンを対象とする。公開形態、公式への提案、収益化は未決定。公式の許諾を得た企画とは表示しない。

## 3. 中心となる体験

### 一つの公演を訪ねる

1. 年表から公演の展示室に入る。冒頭で開催日・会場・概要を確認する。
2. 開催前の告知や発信を、日付に沿って開く。
3. 当日の確認済み情報と、利用できる写真・動画・外部リンクに触れる。
4. 終演後のメンバーごとの発信を切り替えて読む。
5. 後年の回想があれば、別の区画で読む。
6. 関連する楽曲・公演へ進み、出典一覧を確認する。

「当時をたどる」表示では、利用者が進めた時点より後に発表された情報を隠す。「一覧で見る」表示では、全資料と後年の回想を閲覧できる。将来情報の非表示は展示上の演出であり、史実の改変はしない。

### 展示の入口

| 入口 | 内容 | 初期試作 |
|---|---|---|
| 年表 | 公演、リリース、活動上の出来事を年代順に表示 | 対象期間のみ実装 |
| メンバー | 歴代メンバーごとの公開発信を出来事に結び付ける | 展示室内の視点切替 |
| 楽曲 | 作品、初披露、確認できる公演・発言を結ぶ | 対象公演の関連曲のみ |
| 自分の思い出 | 気になる展示を保存する | 後続版で検討 |

## 4. 遊びと展示編集

- 資料を読むと関連する出来事への道が開く。探索済みであることは本人の端末に保存する。
- どのメンバーの記録からでも入れるようにし、閲覧順を強制しない。
- 一つの展示に「まず読む短い要約」と「詳しい記録・出典」を用意する。
- 資料の不足を、架空の会話や生成画像で埋めない。
- クイズ、収集率、ランキングは初期版では採用しない。歴史の理解と資料へのアクセスを優先する。
- 実在の楽曲を再生できない場合も、曲名・関係・正規の視聴先へのリンクで展示を成立させる。

## 5. 史実を扱う編集原則

1. 展示の事実記述は、必ず根拠となる資料・該当箇所に結び付ける。
2. 本人の感情は「本人が、いつ、どの媒体でそう語ったか」として紹介する。第三者が内面を推定しない。
3. 開催日、発表日、投稿日時、後年の回想日時を別に管理する。
4. 予定と実施を区別する。開催告知だけで開催済みとは判定しない。
5. 数字や日付が食い違う場合は両方の根拠を残し、未解決のまま断定しない。
6. 公開資料で分からないスタッフ判断・舞台裏・因果関係は「不明」とする。
7. 生成AIの文章は編集案として扱い、承認前の文章を公開しない。
8. 実在人物の架空の台詞、音声模倣、架空の手紙を展示の資料にしない。

## 6. 資料の対象と「全て」の定義

対象は、結成から収集基準日までのグループ公式媒体および歴代全メンバーの、公開されている活動関連資料。研究生時代・結成以前は、必要性と公式性を確認した補足展示として別に扱う。

収集基準日の初期値は2026年11月8日（日本時間）。この日以降に予定される公演は「予定」として別管理し、実施済みの歴史に混ぜない。

「全て」は、対象媒体・アカウント・期間を台帳に登録し、取得済み・未取得・閲覧不可・削除確認済みなどの状態を説明できることを目標とする。存在や件数を確認できない資料について、網羅を保証しない。取得失敗を削除と判定しない。

一次資料を中心とし、主催者・会場・レーベル・インタビュー媒体は照合用に扱う。ファンの記録は発見の手掛かりとして別枠に保存し、公式記録と同列に扱わない。一般ファンの投稿を網羅的に収集することは初期対象外。

## 7. 収集と展示の範囲を分ける

研究用データに記録した資料を、そのまま全文・画像・映像として公開する設計にはしない。出典情報、事実の要約、短い必要な引用、公式の外部リンクを基本とし、原文・画像・動画の保存と展示可否は資料単位で管理する。

公開展示に使えるか確認が済まない素材は表示しない。出典リンク中心でも見られる展示を標準とする。有料・会員限定資料、削除資料、転載物は初期の自動取得対象に含めない。

## 8. 最初の試作

**一つの実在する公演と、その前後の資料を使った、一展示室。**

- 公演候補を最大3件比較し、資料の充実度、全メンバーの視点の有無、日時の確実さで選ぶ。
- 開催前後30日を初期探索範囲とする。関連する重要な告知と後年の回想は、日付を明示して追加する。
- 公開・承認済みの資料カード20〜40件程度を目安とする。件数のために無関係な資料を入れない。不足は不足として示す。
- 公演概要、時系列、メンバー視点、関連曲、出典一覧、資料不足の説明を用意する。
- 実際の来場者数、セットリストなどは根拠が得られた項目のみ掲載する。

## 9. 成功の判定

ファン2〜3人と、詳しくない人2〜3人に試してもらう。まず次のタスクを観察する。

1. 公演がいつ、どこで開かれたかを見つける。
2. 同じ出来事について、別のメンバーの記録を見つける。
3. 一つの記述の出典を開く。
4. 当時の発信と後年の回想を見分ける。

試作の目標は、補助なしで各タスクを完了できることと、本人の言葉と編集要約を取り違えないこと。「新しく知ったつながり」と「もっと見たい入口」を聞き、次の展示の判断に使う。公開前は全事実記述に根拠が付いていることを必須とする。

## 10. 進め方と判断点

| 段階 | 成果物 | 次に進む条件 |
|---|---|---|
| 1. 資料調査 | 歴代人物・媒体・アカウント台帳、取得可能性一覧 | 未確認対象と欠落を明示 |
| 2. 一公演の編集 | 出来事、根拠、資料カード、展示構成 | 史実・引用・素材の確認完了 |
| 3. 試作 | スマートフォン・PCで閲覧できる一展示室 | 受け入れテストを通過 |
| 4. 観察・改訂 | 利用者の理解と迷いの記録 | 次の展示・入口を選択 |
| 5. 展開検討 | 年表拡張、公開・公式提案の判断 | 公開範囲と素材の扱いを確定 |

現時点では費用や日程を断定しない。最初の調査で媒体ごとの取得方法と一展示あたりの編集負荷を測り、その実測で見積もる。

## 11. 直近の具体的な作業

データ収集AIは、まず公式サイトを起点に台帳を作り、公演候補3件を根拠付きで提案する。企画者は候補から一公演を選び、「この展示で知ってほしいこと」を一文で決める。開発AIは収集完了を待たず、承認済みの少量データを差し替えられる展示構造を準備する。ただし未確認の内容を事実として補完しない。
