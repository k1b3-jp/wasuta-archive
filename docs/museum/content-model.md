# 表示に依存しない資料・史実モデル

設計方針：2026-11-08。今後のモデル設計の正本。全体の論理設計。収集・保存層は[収集運用](collection.md)のとおりローカルに部分実装したが、事実記述・展示構成までの全体移行を示す文書ではない。現状の実装は data-dictionary.md の1.0と20261108000000のmigrationを参照する。

## 決定

公演の展示室、年表、人物ページ、楽曲ページ、比較表示、検索結果で同じ資料・根拠を再利用できるよう、対象・原資料・根拠付き記述・編集文章・展示構成を分離する。データの所有者を画面や展示室にしない。汎用性は画面非依存と多対多の関連で確保し、すべてを自由なJSONや外部キーのないtype/idペアに置き換えない。

既存events/members/songs/costumes/milestones/youtube_linksと既存ID・URLは維持する。公演以外の資料も公演IDなしで登録できる。一つの資料を複数公演・人物・楽曲に接続しても複製しない。展示に採用されない資料も存在できる。

## 1. 対象と活動上の関係

対象は既存の型別テーブルを利用する。汎用nodesテーブルへ移さない。公演の日付や会場等の既存列は既存画面との互換性を維持し、将来の確認済み記述から更新する場合も監査付きの明示的な反映処理を通す。旧登録値を自動で確認済みにしない。

出演・演奏・着用はそれぞれevent_members/song_events/costume_events等の型別関連を維持する。関係そのものにも根拠を関連付ける。記事が曲を「言及した」ことと、その公演で「演奏された」ことを同じ関連にしない。後者には演奏の根拠を必要とする。

## 2. 発信主体・アカウント・原資料

|論理テーブル|主な内容・関係|
|---|---|
|publishers|組織・媒体の発行主体。人物は既存membersを参照する|
|accounts|媒体、プラットフォーム不変ID、公式性の確認状態。所有者と記事の著者を別管理|
|account_owners|account_idとmember_idまたはpublisher_id、所有期間。型別FKと排他制約|
|account_identifiers|handle・URLと有効期間。改名、移転、旧URL。名称やURLを主キーにしない|
|account_evidence|公式性・所有関係の根拠となる資料の該当箇所。時点と確認者を保持|
|source_records|公開前も保存できる原資料の登録。account_id、投稿ID、資料種別、書誌。source_idは公開書誌を作成するまでnull|
|source_locations|原URL、移転先URL、正規URL、合法的なアーカイブURLと関係・確認時点|
|source_contributors|著者、投稿者、取材者、発行者などの役割。人物または組織への型別FK|
|source_versions|訂正・移転等で確認した版、版の公開日時、取得日時、変更概要。元発信日と移転先の掲載日を分離|
|passages|source_version_id、段落・見出し・動画時間範囲などのlocator。原文の保存は権利条件を満たす場合だけ|
|coverage_runs|アカウントと調査期間、方法、取得件数、総件数の根拠、取得不能範囲、再開位置|

既存sourcesは匿名から書誌情報を読めるため、未承認書誌の保管先にしない。source_recordsを非公開の収集・編集領域とし、人が書誌の公開を承認してから既存sourcesと一対一で接続する。既存公開sourcesを取り込む場合も逆方向の一意な対応を作る。原資料の正本と公開向け書誌の投影を区別し、両方を独立に手修正して不整合を作らない。

同一性は(account_id,platform_post_id)等で確認する。投稿IDのないWeb資料は確認した正規URL等で重複候補を検出し、同一と決め付けず監査付きで統合する。転載・引用元・移転版の関係も保持する。

## 3. 根拠付きの事実・本人の発言

|論理テーブル|主な内容・関係|
|---|---|
|assertions|記述の不変ID。種別：event_fact / attributed_statement / editorial_interpretation|
|assertion_versions|記述の版、文意、対象期間、確からしさ・矛盾状態。公開後に版を上書きしない|
|assertion_evidence|assertion_version_id ↔ passage_idの多対多。supports / contradicts / mentionsを区別|
|assertion_events / assertion_members / assertion_songs等|対象・話者・言及対象などの役割を持つ型別の関連。実FKを設ける|
|assertion_conflicts|食い違う記述間の関係、解決状態、採用判断・理由|

「4月29日に初披露した」と「本人が年末に初披露だったと記した」は別の記述である。本人の内面を推定せず、発言者と発言時点を持つattributed_statementとして記録する。回想を根拠に過去の出来事を確定する判断はevent_factの別レビューにする。

頻出する史実（公演日・会場・実施/中止、演奏/初披露等）は型付きの記述・関連として扱う。述語は管理された語彙にし、任意文字列と自由な値だけのEAVにしない。各述語の値型、対象数、必須の役割、日付・根拠の制約をmigrationで定義する。関連の出典は単なる資料URLでなくassertion_versionとpassageへ戻れるようにする。

## 4. 編集文章と素材利用

|論理テーブル|主な内容・関係|
|---|---|
|editorial_texts / editorial_text_versions|見出し・編集要約・解説など。原資料や史実レコードから独立したIDと版|
|text_assertion_links|文章の範囲と、その記述が依拠するassertion_versionの対応。段落一括で異なる事実を曖昧にしない|
|quotations|出典passage、引用範囲、話者、引用目的、権利・編集確認。要約とは別の表現形式|
|asset_usage_permissions|既存media_assetsや資料の素材、用途（リンク/引用/埋め込み/複製）、条件、根拠、期限、確認日時|

同じ根拠から短いカード文、詳しい解説、比較用の文章を作成できる。文章を変えても史実・原資料を複製しない。本文に含まれる事実の追加は根拠との関連付けと再レビューを必要とする。

資料を読めること、要約を公開できること、画像や原文を転載できることは別の許可である。公開されている資料を理由に画像等の利用可へ昇格させない。

## 5. 展示構成と表示用読み取り

|論理テーブル|主な内容・関係|
|---|---|
|collections|特集・展示のまとまり。公演展示、人物特集など。原資料を所有しない|
|collection_sections|任意の章、表示名、並び順。開催前/当日/終演後/回想もここで編集できる|
|collection_entries|既存対象、資料の該当箇所、記述、編集文章への参照と順序。参照は型別FKまたは排他的FK列で保証|
|collection_releases|人が承認した構成・文章・根拠の版の組み合わせ。再現できる公開単位|

年表・メンバー・楽曲等の画面は承認済みデータを条件で組み合わせた読み取りモデルとして構成する。すべての画面にcollectionの手編集を要求しない。collectionは企画展示に必要な編集順序・見出しだけを持つ。UIコンポーネント名、カードの色、画面の列数は根拠データに持たせない。レイアウト指定が必要なら表示側の設定に閉じ込める。

「開催前」は対象公演との相対的な区分。一つの記事が公演Aには終演後、公演Bには開催前になるため、原資料の固定属性にはしない。「後年の回想」は日付の差だけで自動確定せず、対象の記述と資料の関係も確認する。

## 時間の共通規則

分けて管理する時間：出来事の発生日/期間、資料の元公開日時、移転・訂正版の公開日時、発言・取材日時（判明時のみ）、取得日時、編集・承認日時。

日付表現はday/month/year/range/unknownと原表記、時刻が判明した場合のみoffset付きtimestampを保持する。月・年を便宜的な1日・元日の事実にしない。検索用の範囲を導出しても表示・確認済み日時と混同しない。未確定の上下限やタイムゾーンも明示する。

「当時をたどる」は原公開時点を確認できる資料・記述だけを、その時点の版で返す。いまの承認日を過去の公開日に置き換えない。後から判明した事実を当時知り得た情報として混入させない。必要な旧版が確認できなければ、完全な当時再現を保証しない。

## 承認・RLS・版の依存関係

- 収集・同定、史実の裏付け、編集文章、素材用途、展示の公開を別々に確認する。
- 既存rankと監査ログ、監査付きRPCを使い、直接の状態更新は許可しない。AIの抽出はdraft/pending。
- 公開の必要条件は、構成・文章・参照する記述の版・該当箇所の公開・書誌・用途許可がすべて承認済みであること。構成の承認だけで参照先を昇格させない。
- 未確認資料のlocatorと書誌は非公開領域で保管し、研究データをpublicスキーマの既存全公開表へ先に投入しない。
- 根拠や許可が取り下げられた場合、公開済みの版を参照していても依存する公開結果を閉じる。古い版を固定したことを理由に取り下げを無視しない。訂正後は新しいreleaseを人が承認する。
- 失効・取り下げはHTMLだけでなくAPI、検索インデックス、生成ファイル、キャッシュにも反映する。取り下げ対応を定義できるまで、無期限の静的公開スナップショットを増やさない。

## 今回の最小版からの移行

1. 追加型migrationとして非公開のsource_records/accounts/versions/passagesを先に実装し、匿名・editor・reviewerのRLSと取り下げのテストを用意する。既存sourcesの公開契約は黙って変更しない。
2. 6件の調査カードを原資料・版・該当箇所・記述・編集文章へ分ける。research_keyとの対応表を維持し、再実行で同じものを新設しない。新規に分けたレコードはすべて未承認。
3. event_exhibit_cards.phaseは展示区分へ、summaryは編集文章へ、locatorはpassageへ、発信日時は資料の版へ移す。event_idは記述の対象と展示の文脈へ移す。member_id/speakerは著者・話者を照合して分離する。
4. 既存のExhibit表示型を返す変換層を作り、既存イベントURL・現在の展示UIを維持する。変換結果は正本にしない。
5. 同じ資料を公演展示・メンバー一覧・楽曲ページの3種類から読む実装で、資料の複製なし、元公開日時の維持、共通の取り下げを検証する。
6. 新旧読み取りを比較してから旧カードの書き込みを停止する。現段階では旧表の削除・本番適用・実資料公開を行わない。

## 次の実装の受け入れ条件

- 公演IDなしの資料、一記事で複数公演、一資料で複数著者、一主張で複数根拠を表現できる。
- 同じ資料・根拠から異なる長さの編集文章を承認し、年表・人物・公演展示に重複保存なしで表示できる。
- 公演に対する前後関係を変えても元公開日時が変わらない。
- 資料の移転・訂正、日時不明、矛盾、引用不可、本文未取得を情報を補作せず表現できる。
- 未承認資料の書誌・本文・関係が匿名のHTML/API/配布物へ出ない。
- 根拠・本文・素材許可・展示のいずれかの取り下げが、全表示に反映する。
- 既存の型別FK、ID、URL、承認・監査経路を維持する。


## 現在の実装範囲（2026-11-08追補）

収集層では `archive_research` にアカウント、識別子、原資料、取得版、観測履歴、発信者、版に属する該当箇所、同定根拠、編集案、取得範囲、監査を実装した。上記の論理テーブルすべてが存在するわけではない。特に根拠付き記述、編集文章、展示構成の分離は設計段階で、既存展示カードの読み取りを維持している。

API由来の資料とブラウザの部分観測は原資料の投稿IDで結び、取得方法・表現の精度・版を分ける。ブラウザのアクセシビリティ要約は全文や本人の引用へ昇格しない。該当箇所と編集案を版ごとに残すことで、将来どの見せ方を採用しても根拠の版をたどれる。取り込みと削除抑止は資料単位のロックを共有し、取得失敗と再開位置は非公開DBに記録する。具体的な契約は[データ辞書](data-dictionary.md)、取得実績と欠落は[収集運用](collection.md)を参照。
